# Как <это> ваще использовать

> [!IMPORTANT]
> В данный момент работа проверена только на Linux:  
> Дело в том, что алгоритм завязан на Linux-специфичных вещах, 
> таких как /dev/urandom, /proc/self/maps и /proc/sys/kernel/random/boot_id  
> в Linux это решается созданием символических ссылок на первый и последний;  
> для /proc/self/maps можно просто вернуть снятый с реального устройства дамп - алгоритм,
> похоже, не проверяет соответствие адресов и прочие аспекты.  
> В настоящее время код мокает любой путь, если он существует после подстановки ./, т.е:  
> если в директории [java](./java) создать директории proc/self, а внутри создать файл maps, в который поместить дамп реального maps, то код вернёт его контент;  
> тоже самое можно провернуть с /dev/urandom и /proc/sys/kernel/random/boot_id

# Сборка(?)
- Клонируйте репо
- Перейдите в директорию [java](./java)
- Запустите
    ```bash
    ./gradlew shadowJar
    ```


# Генерация токенов
- Запустите собранный jar(должен быть где-то в [java/build/libs](./java/build/libs))
    ```bash
    java -jar <jar> <libs dir> <method> <path>
    ```


### Что есть что
- jar
    > ваш jar из [java/build/libs](./java/build/libs)
- libs dir
    > директория, где лежат библиотеки(bnit и его зависимости, а это:  
    > libc++_shared.so  
    > libcrypto.so  
    > libssl.so  
    >)(все библиотеки можете найти внутри apk самого Lane)
- method
    > GET | POST | ...
- path
    > /user/playlists | /user/artists | ...


### Как использовать внутри других языков
Пока что рабочий вариант - использовать cli интерфейс. jar выплёвывает в stdout json с токенами, что-то типа
```json
{
    "x-core-token": "...",
    "x-client-meta": "...",
    "x-request-trace-id": "..."
}
```
Просто читаете stdout, парсите json и используете как хедеры в запросе(можете глянуть примеры запросов [тут](./http-request-dumps))
